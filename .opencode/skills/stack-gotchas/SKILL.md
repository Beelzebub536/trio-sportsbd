# Stack gotchas

Always confirm details against current docs (context7) for the versions in package.json. These are the traps free models most often hit.

## Next.js (latest, App Router)
- `params` and `searchParams` are Promises in pages/layouts/route handlers: `const { slug } = await params`.
- `cookies()` and `headers()` are async: `await headers()`.
- Newer versions rename `middleware.ts` to `proxy.ts`. Check the installed version's docs for the file name and export name. The proxy only does a fast redirect for signed-out users; real authorization is in server code.
- Caching APIs changed between versions (`revalidateTag`, `revalidatePath`, `use cache`). Read the installed docs before using them. After admin edits (prices, stock, products) the storefront must show fresh data: revalidate the affected paths/tags in the same server action.
- Use `next/image`; Cloudinary host must be in `images.remotePatterns` (or use `res.cloudinary.com` loader).
- Use `next/font/google` for fonts (self-hosted at build, no runtime request).

## Prisma + Neon
- Check which Prisma major is installed. Newer majors require: a `prisma.config.ts`, an explicit `output` in the generator, and a driver adapter (`@prisma/adapter-neon` or `@prisma/adapter-pg`) when instantiating the client. Do not write old-style code from memory.
- Two connection strings: pooled (`DATABASE_URL`, host contains `-pooler`) for runtime, direct (`DIRECT_URL`) for migrations/push.
- Singleton client in `src/lib/prisma.ts` (avoid new clients on hot reload).
- `package.json` scripts: `postinstall: prisma generate` so Vercel generates the client. Also `db:push`, `db:seed`, `db:studio`.
- Windows: if `prisma generate` fails with EPERM on query_engine, stop the dev server and retry.
- Use `$transaction` for anything that touches several rows (orders+stock, bulk prices).

## Better Auth
- Auth tables are generated by the Better Auth CLI (`npx @better-auth/cli generate`), then merged into schema.prisma. Do not hand-write them from memory.
- Server instance `src/lib/auth.ts`: `prismaAdapter(prisma, { provider: "postgresql" })`, `emailAndPassword: { enabled: true }` (NO email sending, no verification, no reset email), `socialProviders: { google, facebook }` enabled only when env keys exist, `admin` plugin with `adminRoles: ["admin"]` and default role `customer`, `nextCookies()` plugin LAST in the plugin list.
- Route handler: `src/app/api/auth/[...all]/route.ts` using `toNextJsHandler(auth)`.
- Client `src/lib/auth-client.ts`: `createAuthClient()` + `adminClient()` plugin.
- Server session: `auth.api.getSession({ headers: await headers() })`.
- Roles: signup must never be able to set its own role (make sure `role` is not user-settable on input). First admin is created only by the seed script from `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
- Account linking: Google may auto-link (`trustedProviders: ["google"]`). Do NOT auto-link Facebook (emails not guaranteed verified; takeover risk).
- OAuth callbacks: `{BASE}/api/auth/callback/google` and `{BASE}/api/auth/callback/facebook`.
- No password-reset email exists: admin resets passwords from the admin panel (admin plugin `setUserPassword`).

## Tailwind / shadcn
- Check which Tailwind major is installed (v4 uses CSS-based config in `globals.css`, no `tailwind.config.js`). Use `npx shadcn@latest add <component>`; the shadcn MCP can list components.
- Adidas look needs `--radius: 0` (sharp corners).

## Vercel
- No long-running processes, no websockets, no writing to local disk at runtime. Uploads go to Cloudinary. Keep server actions fast; Neon may take ~1s to wake from idle.
- All env vars must be listed in `.env.example` and validated at startup with Zod in `src/lib/env.ts` (clear error message when something is missing).
